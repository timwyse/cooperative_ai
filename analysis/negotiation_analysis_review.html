4. Tactics Taxonomy

Anchoring (detected in 20.9% of negotiations)

The first proposal contains extreme asymmetry -- one player opens with a demand for 16+ points or a 3:1+ tile ratio, setting an aggressive anchor for the negotiation.

Take-it-or-leave-it (detected in 0.4% of negotiations)

Agreement is reached in 3 or fewer non-system messages. The proposer makes a single offer that is accepted without substantive counter-proposals.

No-deal Walk-away (detected in 11.6% of negotiations)

Negotiation ends without agreement. Players reject the proposed contract or explicitly state they do not need cooperation.

Power Asymmetry (detected in 52.9% of negotiations)

Mutual Verification (detected in 41.0% of negotiations)

Both players engage in coordinated verification of tile positions, chip costs, and path feasibility, using words like 'verify,' 'confirm,' or 'check' alongside coordinate references.

Path Analysis (detected in 92.0% of negotiations)

Players present detailed path calculations using arrow notation (e.g., (0,0) -> (1,0) -> ...) or enumerate chip costs for specific routes.

Deception (suspected) (detected in 7.3% of negotiations)

A player states chip counts inconsistent with earlier claims or reverses agreed terms during the agreement phase. Flagged for manual review.

Incremental Concessions (detected in 30.9% of negotiations)

Extended negotiation (6+ messages) with multiple numeric proposals showing progressively smaller gaps, indicating gradual convergence toward a deal.

6. Classification Methodology

All tactics are classified using deterministic heuristics (keyword and pattern matching on negotiation transcripts). No LLM calls are used for classification. Each log file is parsed from game.turns.<N>.contract_negotiation, which contains two conversation histories (one per player) and the final agreement/contract.

Anchoring

Examines only the first assistant message in the negotiation.

  • Finishing contracts: Triggered if any number between 16 and 20 appears near keywords ("point", "give", "transfer", "pay", "receive"), or if an explicit 0/20 pattern is found.
  • Strict contracts: Triggered if the first proposal mentions tile/chip/resource counts in a ratio of 3:1 or greater.

Take-it-or-leave-it

agreement_status == True AND total non-system messages in the conversation <= 3.

No-deal Walk-away

Any of:

  • agreement_status == False
  • Parsed agreement response has status "rejected" or "disagreed"
  • Finishing contract with (0,0) transfer AND messages contain refusal phrases: "don't need", "no cooperation", "refuse", "won't cooperate", "not interested"

Power Asymmetry Exploitation

All non-system messages (both players) are searched for any of these phrases:

"i can reach my goal without" | "i don't need you" | "you cannot reach" | "you can't reach" | "you need me" | "self-sufficient" | "independently" | "without any help" | "without your help" | "don't need cooperation" | "without assistance" | "reach my goal on my own"

Mutual Verification

Both players must independently satisfy two conditions in their own assistant messages:

  1. At least one coordinate reference matching the pattern (digit, digit)
  2. At least one verification word: "verify", "confirm", "check", "correct", "recalculate", "double-check"

The tactic is only flagged if both players meet both conditions.

Path Analysis

Searches all non-system messages for either:

  • Arrow notation: (x,y) -> (x,y) (two or more coordinates connected by arrows)
  • 4+ coordinate references AND at least one cost keyword ("cost", "chip", "spend", "require", "need", "use")

Deception (suspected)

Flagged for manual review if either:

  • Reversal language appears: "actually, i changed my mind", "let me revise", "on second thought", "i lied", "that's not true", "i was bluffing"
  • A player claims different chip counts for the same color at different points (e.g., "i have 5 red" then later "i have 3 red")

Incremental Concessions

Requires all of:

  1. >= 6 non-system messages in the conversation
  2. Extract all numbers 0-20 from each message (taking the max per message as the "proposal")
  3. Compute gaps between consecutive proposals; at least 2 instances where the gap decreases (indicating convergence)

Dominant Tactic

Each negotiation is assigned a single "dominant tactic" using a fixed priority order: No-deal Walk-away > Take-it-or-leave-it > Anchoring > Power Asymmetry > Incremental Concessions > Mutual Verification > Path Analysis > Deception. The first matching tactic wins. Multiple tactics can be true simultaneously; the dominant tactic is just the highest-priority one.

Limitations

  • All heuristics are keyword-based, so they can produce false positives (e.g., "independently" in a non-leverage context) and false negatives (e.g., anchoring phrased without the expected keywords).
  • The "Deception" classifier is particularly coarse -- inconsistent chip counts may reflect legitimate recalculation rather than deception.
  • Incremental Concessions relies on number extraction that doesn't distinguish point proposals from other numeric references (e.g., coordinates, chip counts).
